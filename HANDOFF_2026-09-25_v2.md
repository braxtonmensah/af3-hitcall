## 3. SSH automation — THE important operational fact

**Connection multiplexing works in WSL and does NOT work in Git Bash.** Git Bash's OpenSSH on
Windows cannot pass file descriptors over a Unix socket, so its master authenticates and then refuses
every session with `mux_master_process_new_session: failed to receive fd 0 from client`. Four
attempts were burned on this before the cause was found.

Setup (already done, persists):

- Config at `~/.ssh/config.quartz` **inside WSL Ubuntu**, included from `~/.ssh/config`
- `ControlPersist 12h`, socket at `~/.ssh/cm/%C` on the **Linux** filesystem, never under `/mnt/c`
- Braxton runs `ssh quartz` once in WSL (passphrase + Duo). For 12 hours after that, any command
  works with no prompt:

```bash
MSYS_NO_PATHCONV=1 wsl.exe -d Ubuntu -- bash -lc 'ssh quartz "<command>"'
```

`MSYS_NO_PATHCONV=1` matters: Git Bash rewrites `/mnt/c/...` into `C:/Program Files/Git/mnt/...`
otherwise.

To re-open the login window:

```bash
powershell.exe -NoProfile -Command "Start-Process wsl.exe -ArgumentList '-d','Ubuntu','--','bash','/mnt/c/Users/bmens/wsl_login.sh'"
```

## 6. Bugs caught today that would have cost real runs

- **Decoy set overlapped the screen set.** Decoys were sampled from the whole library while the screen
  took the first 300, so ~5 compounds sat in both arms and capped their own null. Circular, and
  invisible in the output. Now drawn disjoint.
- **24 salts/mixtures and 8 tiny fragments** among 350 jobs. Boltz-2 cannot take a multi-component
  SMILES as one ligand. Now desalted to the largest fragment, identically in both arms.
- **Ligand size filter used the wrong bound.** Boltz-2 rejects >128 atoms *including hydrogens*; the
  filter was 100 *heavy* atoms. CHEMBL413 passed at 65 heavy and is 144 total.
- **CRLF line endings put a carriage return inside the MSA path**, so a file that existed reported as
  missing. `*.yaml`, `*.sh`, `*.slurm` now pinned to LF in `.gitattributes`.

## 7. Quartz gotchas (each cost a cycle)

1. Default python is **3.13.5** and boltz cannot install on it (biopython, dm-tree, gemmi have no
   3.13 wheels). Use `module load python/gpu/3.11.5`.
2. **Do not `module purge`** before loading `python/gpu/*`. It strips the prerequisites, every load
   fails silently, and it looks like no usable python exists while three sit in `module avail`.
3. **Use the `h100-single` partition, not `v100`.** Quartz has both (`h100-single g[39-88]`,
   `v100 g[1-24]`). H100 is sm_90 with native bf16 and is supported by the torch boltz pulls. An hour
   was wasted solving a Volta problem that did not apply.
4. **`torch.cuda.get_arch_list()` returns empty on a login node** whenever CUDA cannot initialise. It
   reported "CPU-only build" for four consecutive builds that all ship sm_70. Never decide GPU
   capability from a login node; ask real hardware with `srun`.
5. Login nodes have internet, **compute nodes do not**. Stage weights on the login node first.
6. Repeated failed SSH auth gets the IP **banned at TCP level** for ~30-60 min.
